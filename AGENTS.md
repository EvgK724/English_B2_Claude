  Do not fill missed dates in bulk. A completed day is a successful no-op.

- Codex prepares content only with `tools/daily_queue.py status/prepare`. Commit
  only the resulting `data/requests/YYYY-MM-DD-<deck>.json`. Do not run speech

- The existing GitHub Actions workflow processes the queue with `daily_deck.py`,
  validates separate Ryan/Andrew coverage and ledgers, then publishes complete
  packs. This execution path was explicitly authorized on 2 November 2026.
  Do not run the historical `sources/*/build.py` files.
- A queued request is immutable. Do not prepare another request for that deck
  while one awaits audio. Retry that approved request after a failure; do not

- Scheduled work may publish only its reviewed daily update to this repository's
  existing `main` branch. Never force-push; inspect a rejected push and reassess

- Scheduling is managed separately in Codex. Do not create additional timers or
  restore the former artifact-to-GitHub transfer task.

## О проекте

60 тренажёров английского уровня B1–B2 в одной оболочке: каталог по группам, «Сегодня к повторению», поиск, озвучка, прогресс.
Интерфейс на русском, примеры и задания на английском. Две живые версии, обе ставятся плиткой на экран «Домой» iPhone и iPad:

- GitHub Pages: https://evgk724.github.io/English_B2_Claude/site/ — собирается workflow `Ryan audio and Pages` из ветки `main`,
  работает без интернета, прогресс — на устройстве (переносится файлом);
- артефакт Claude: https://claude.ai/artifact/15er8g7yJZJ5tCpvRXK3ZM — прогресс синхронизируется через облако claude.ai.

## Запуск

Оболочка грузит тренажёры и звук через `fetch`, поэтому двойной клик по `index.html` не работает — нужен локальный сервер:

```
python3 -m http.server 8000
```

Открыть http://localhost:8000/site/ (офлайн-кэш работает и на `localhost`; при отладке его удобно отключить в DevTools → Application).

## Как вносить изменения

- **Тренажёр**: править `site/apps/<ключ>.html`. Данные — в скрипте: `const TOPICS = [...]` (правила и примеры) и `const CARDS = [...]`. В грамматических тренажёрах карточка — `id`, `t` (номер темы), `q` (вопрос с `___`), `opts`, `a` (правильный ответ), `why`; в словарных колодах (phrasal, bbapp, idm и др.) — `id`, `term`, перевод, примеры. Новые карточки делать по образцу соседних. Интервалы повторения — `const INTERVALS = [1, 3, 7, 16]` (дни), ключ прогресса — `LS_STATE = "<ключ>:state"`.
- **Каталог** (название, группа, описание, ключевые слова для поиска): `tools/catalog.json`, затем `python3 tools/mk_shell.py`.
- **Оболочка**: `tools/shell.html` (и `tools/head.html`, `tools/sw.js`), затем `python3 tools/mk_shell.py`. `site/index.html` и `site/sw.js` вручную не править — перезапишутся.
- **После любой правки в `site/apps` или `site/packs`** — тоже `python3 tools/mk_shell.py`: оболочка обращается к файлам с `?v=<хэш содержимого>`,
  и офлайн-кэш на телефоне берёт новую версию только по новому хэшу. Без пересборки устройство продолжит показывать старый файл.
- **Колоды «Фразовые глаголы» и «Фразы из Breaking Bad»** — только через текущую очередь Codex,
  описанную выше и в `tools/DAILY_DECKS.md`. Старые артефакты не являются источником ежедневных обновлений.
  Справка о прежнем ручном импорте сохранена в [docs/generator-reference.md](docs/generator-reference.md#прежний-ручной-импорт-колод).
- **Звук**: записи тренажёра склеены в `site/packs/<ключ>.mp3`, смещения — в `tools/packs.json`. Пакеты грузит сама оболочка
  (`loadPack`: сначала своя копия в кэше `eng-b2`, иначе сеть и копия на будущее), офлайн-кэш `sw.js` их не трогает —
  так звук не зависит от его работы. Если запись не прозвучала, тренажёр говорит голосом устройства, а внизу темы
  один раз появляется подсказка (`AE.fail`). «Проверка звука» внизу главного экрана проигрывает одну запись всеми способами
  (blob, в iframe, data:, файл, Web Audio, голос устройства) и пишет, что сработало, — для диагностики на телефоне. Если у фразы нет записи, тренажёр озвучивает её синтезом речи браузера (`TTS_LANG = "en-GB"`). Исходных записей в проекте нет; как их обрезали и склеивали — `tools/reference/audio.py` (нужен ffmpeg).
- `id` карточек не менять: по ним хранится прогресс пользователя.
- **Подробности отдельных тренажёров и старых генераторов** — в [docs/generator-reference.md](docs/generator-reference.md).
  Перед изменением соответствующего тренажёра прочитать его раздел: там сохранены назначение, положение в каталоге,
  различия с соседними темами и особенности звука. Команды старой сборки приведены только для справки;
  текущий запрет на запуск `sources/*/build.py` сохраняется.

  их воспроизведение на опубликованном сайте. После любого изменения MP3 пересобирать оболочку,

- **Автоматическая озвучка новых слов и фраз (23 октября 2026).** После добавления или изменения

  Отдельная просьба пользователя об озвучке не нужна. Существующие записи с совпадающими текстом и

## Правила оформления

Внешний вид — как у приложения want-you-to из репозитория test01, и задаётся одним файлом `site/theme.css`.
Он подключается в оболочке и в каждом тренажёре (через `HEAD` в `tools/shell.html`) поверх их собственных стилей:
переменные — в `:root:root{…}` (перекрывает `:root` тренажёра), правила для тренажёров — с префиксом `:root .app`.
Сами тренажёры поэтому не правятся, и оформление переживает их пересборку из `sources/`. Новый тренажёр
получает оформление автоматически, если пользуется теми же переменными (`--bg`, `--surface`, `--accent`, `--blue`, `--serif`, `--sans`…).

- Фон `#0b0d12` со свечением по углам (`--glow`), панели — градиент `--panel-grad` с тенью `--shadow`.
- Текст `#ece8e1` (не чистый белый), второстепенный `#a3a8b5`. Акценты: янтарный `--v` (#f2b766, он же `--accent`),
  бирюзовый `--o` (#5fd0bf, он же `--blue`), сиреневый `--i` (#a9b2ff); верно `#7dd197`, ошибка `#f07468`.
- Главная кнопка — тёмная с янтарным оттенком (`--primary-bg`, рамка `--primary-line`, текст `--primary-fg`): заметная, но не слепит;
  вторичные — тёмные панели; кнопки озвучки — круглые.
- Шрифты: английский и заголовки — Bricolage Grotesque (`--serif`; кириллица в нём берётся из Golos Text),
  русский — Golos Text (`--sans`), транскрипция — Gentium Book Plus (`--ipa`, классы `.ipa`, `.w-ipa`). Файлы лежат в `site/fonts`,
  поэтому всё работает без интернета и без Google Fonts.
- Крупный шрифт, кнопки не меньше 44×44 px, управление большим пальцем внизу экрана.
- Окно — во весь экран до самого низа: `.shell` — `position:fixed` на весь экран, отступы под вырез и полоску «Домой» —
  только у содержимого (`env(safe-area-inset-*)`). Внутри тренажёра (iframe) `env()` равен нулю, поэтому оболочка передаёт
  нижний отступ переменной `--sab`, и `theme.css` ставит нижние кнопки `.app` сразу над полоской «Домой».
  Строка состояния — `black-translucent` (по просьбе пользователя 23 октября 2026): текст при прокрутке уходит под часы
  до края экрана, под часами — лёгкое затемнение `.sfade`. С прозрачной строкой iOS 26–27 делает окно приложения
  на экране «Домой» короче экрана на высоту этой строки, и внизу остаётся чёрная полоса (WebKit 301108; масштаб Safari
  ни при чём — у пользователя полоса была и при 100%, iPhone 18 Pro Max, iOS 27). Обход — в `tools/head.html`:
  `@media (display-mode:standalone){html{min-height:min(100lvh,calc(100% + env(safe-area-inset-top)))}}` — страница
  не ниже экрана, и iOS отдаёт ей окно целиком (пользователь подтвердил на iPhone 18 Pro Max, iOS 27: полосы снизу нет,
  текст уходит за оба края); при сплошной строке (вырез 0) правило ничего не меняет. Высоту самой
  оболочки через 100lvh не задавать: WebKit всё равно не рисует фиксированные элементы ниже короткого края.
  С 4 по 23 октября стояла `black` (сплошная строка) — тогда полосы снизу нет, но и текст под часы не уходит.
  Эти meta-теги iOS запоминает при установке: после их смены плитку ставят заново (прогресс — сначала «Сохранить прогресс»).
- Переносы — только между словами (просьба пользователя 23 октября 2026). `theme.css` запрещает рвать слово между буквами
  (`overflow-wrap`, `word-break`, `hyphens` для всех элементов). Оболочка (`watchNobr` в `tools/shell.html`, и для самой оболочки,
  и для каждого тренажёра через мост) оборачивает в `.nobr` слова через дефис (white-water, flu-like, -ing, кто-то) и числа
  (50–69%, 2,5–3,5, 1–3–6–12, 10 000), заменяет неразрывные пробелы между английскими словами обычными (кроме кнопок),
  а если слово не помещается в кнопку ответа или ячейку таблицы — уменьшает шрифт (`fitOpts`: кнопки до 12 px, ячейки до 60 %).
  Данные тренажёров не меняются — ответы, поиск и записи Ryan не затронуты. Проверено на всех 60 тренажёрах при ширине 320 и 375.
- Страница темы целиком не прокручивается: прокручиваются только её области (`.card`, `.rule` и т. п.), а
  `document.scrollingElement.scrollHeight` равен высоте окна. Элемент с `position:absolute` без позиционированного
  предка не должен стоять ниже экрана: до 25 октября 2026 скрытые подписи `.sr` в списках правил растягивали страницу
  55 тренажёров на тысячи пикселей, и iPhone иногда сдвигал её — текст уезжал вверх, снизу оставалось пусто.
  Теперь `theme.css` ставит `.sr` в левый верхний угол (`top:0;left:0`). Проверено на всех 60 тренажёрах
  (вкладки, раскрытые темы; 320×640, 440×956, 820×1180, 1180×820).
- Без горизонтального скролла; проверять ширины 320, 375, 390, 430 (iPhone), 820×1180 и 1180×820 (iPad).
- В русском тексте — неразрывные пробелы после предлогов и между числом и единицей, тире с неразрывным пробелом перед ним.
- Язык объяснений — русский; примеры, задания и ключи — английский.

## Прогресс и облако

Прогресс хранится в `localStorage` (у каждого тренажёра свой ключ). Счётчики «N/M» у тем в тренажёрах и «N из M» на главном экране
считают карточки, которые тренировали хотя бы раз (`learnedIn`, `statsOf`), — они растут уже после первой тренировки;
интервалы повторения (`step`, `due`) от этого не зависят. Так же считают и шаблоны в `sources/` — не возвращать условие
`step >= 1`: до 24 октября 2026 оно оставалось в шаблонах, и 14 тренажёров, собранных по ним (bare, clauses, during, encour,
havea, incr, indq, like, nverb, oblig, sounds, vnoun, whatfor, without), показывали прогресс темы только со второй тренировки. В опубликованном артефакте он ещё синхронизируется
между устройствами через `window.claude` (возможности `db` и `user`); вне claude.ai этого объекта нет, и всё работает на `localStorage`.
Тогда внизу главного экрана показан блок «Прогресс»: «Сохранить прогресс» отдаёт файл `english-progress-<дата>.json`
(на iPhone/iPad — через меню «Поделиться»: AirDrop, «Файлы»), «Загрузить прогресс» сливает файл с текущим прогрессом
по времени ответа (`ts`), как при слиянии с облаком. Офлайн-кэш (`sw.js`) регистрируется тоже только вне claude.ai.

## Публикация

**GitHub Pages.** Settings → Pages → **GitHub Actions**. После отправки изменений в `main` workflow
`Ryan audio and Pages` проверяет извлечение текстов, создаёт Ryan для новых/изменённых фраз, проверяет
полное покрытие и лишь затем публикует сайт. Созданные MP3, индекс и состояние сохраняются в `main`
коммитом `github-actions[bot]`. Артефакт публикации содержит корневой `index.html` и папку `site/`,
поэтому прежняя ссылка `/English_B2_Claude/site/` сохраняется. Сборка без полного Ryan не публикуется;
при временном сбое проверка повторяется каждый час (GitHub может задерживать запуск по расписанию).
Сравнение с публичной оболочкой также позволяет повторить неудавшуюся публикацию после сохранения аудио.
Не возвращать раздачу прямо из ветки: она обошла бы проверку готовности звука.
Установленная плитка получает успешное обновление при следующем запуске с интернетом; прогресс не сбрасывается.
Ручной запуск с `verify_tts: true` проверяет новую карточку без аудио и восстановление пропавшей записи
через настоящий Ryan в изолированной копии, не меняя учебный материал. Проверки: `node --test tools/test_audio_clips.mjs` и
`python3 -m unittest discover -s tools -p 'test_ensure_ryan_audio.py' -v`.

**Существующий артефакт: совместимость.** Основная работа ведётся в ChatGPT/Codex с GitHub Pages.
Существующую публикацию и её прогресс сохранять; эта миграция её не обновляет. Если пользователь отдельно
попросит обновить именно артефакт, файлы из `site/` должны попасть в ту же публикацию через доступный
инструмент артефактов, чтобы сохранить ссылку и плитки. Ниже описан формат этой версии.
У `site/index.html` при этом убирают `<head>` из `tools/head.html` (всё до `<body>` включительно) и хвост `</body></html>`:
платформа добавляет свой каркас, поэтому `theme.css` в артефакте подключают так же — `<link>` в начале страницы.
`theme.css` и `fonts/` публикуются вместе с остальными файлами; `sw.js`, манифест и иконки в артефакт не нужны.
Сейчас артефакт — в прежнем оформлении: его страница этим репозиторием не обновлялась.
В артефакте пять самых больших пакетов (abbr, htp, idm, irreg, pairs) лежат в хранилище артефакта, поэтому там
список `ASSETS` в `index.html` не пустой; в этой локальной сборке все пакеты — обычные файлы, и `ASSETS = {}`.
