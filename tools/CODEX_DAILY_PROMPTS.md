# Codex daily task prompts

These prompts describe one run. The two schedules and cloud environment selection
are managed separately. Do not recreate or alter schedules from these prompts.
Each prompt is self-contained; it does not depend on a file outside this repository.

## Фразовый глагол дня

```text
Обнови колоду phrasal в существующем репозитории https://github.com/EvgK724/English_B2_Claude, ветка main. Приложение: https://evgk724.github.io/English_B2_Claude/site/. Пользователь разрешил готовить дневной JSON в Codex, а озвучивать и публиковать его через существующий GitHub Actions. Не меняй другие приложения, Potter, Englex, Claude-артефакты или расписания.

Начни с чистого изолированного checkout актуального main; прочти AGENTS.md, tools/DAILY_DECKS.md и последние карточки site/apps/phrasal.html. Для подготовки достаточно Python 3.11+ и стандартной библиотеки. Не запускай TTS в Codex Cloud, daily_deck.py append, daily_queue.py process или исторические sources/*/build.py. Не устанавливай speech-зависимости в облаке, не меняй сеть, прокси, TLS, permissions, credentials и не создавай PAT или платные сервисы. Не используй запрещённый gh-путь. Если разрешённый инструмент вернул отказ, останови именно это действие и сообщи причину; не обходи отказ другим транспортом.

Выполни python tools/daily_queue.py status phrasal. Дата определяется в Asia/Yekaterinburg. При complete не добавляй карточки: заверши без дубликатов. При queued не готовь новый запрос, в том числе если ожидает вчерашний; проверь существующий запуск Actions и сообщи его состояние. При conflict остановись и сообщи точную причину. Только при pending подготовь ровно один новый полезный фразовый глагол. Пропущенные даты не наверстывай, существующие запросы не редактируй.

Проверь все существующие IDs/terms, значение, управление и употребление по надёжному словарю через доступные разрешённые инструменты. Сохрани прежний стиль: британская IPA и формы глагола; переходность и разделяемость; короткий русский перевод; понятное объяснение употребления, типичная ошибка и отличие от близкого выражения; собственный естественный пример B1–B2 с переводом. Медицинские примеры обозначай вымышленными и не вводи непроверенных лечебных утверждений.

Создай вне репозитория batch JSON с ровно двумя верхними полями date и cards. cards содержит один объект с полями id, au:1, added, term, ipa, pos, ru, note, ex, exru, sources. date и added равны дате из status. sources — непустой список проверенных источников с реальными HTTP(S) URL без credentials и title; сохрани полезные сведения о проверке. Все учебные поля — непустые однострочные строки, id — уникальный slug. au:1 означает требуемый итог после Actions, а не наличие звука сейчас. Итоговый голос — Microsoft Ryan en-GB-RyanNeural, две записи term/ex, rate -5%, pitch +0Hz, volume +0%; другой голос или браузерный fallback для публикации недопустимы.

Выполни python tools/daily_queue.py prepare phrasal /absolute/path/batch.json, затем python tools/daily_queue.py verify, python -m unittest discover -s tools -p 'test_daily_queue.py' -v и git diff --check. Просмотри JSON, источники и diff. Результат prepare должен менять только data/requests/YYYY-MM-DD-phrasal.json. Сохрани IDs, прогресс, интервалы, оформление, контент и старое аудио. Не редактируй site/, MP3, индексы, состояния голосов или дневные журналы вручную.

Закоммить и отправь только точный новый request JSON в main обычным push без force через уже разрешённый Git-путь. Если среда предоставляет GitHub connector вместо Git-публикации, используй его поддерживаемый atomic commit/ref с ожидаемым свежим SHA или exact-path create, отклоняющий существующий файл; не перезаписывай запрос. Public fetch и up-to-date dry-run не доказывают право настоящей записи. Если поддерживаемая публикация недоступна, сохрани подготовленный JSON и сообщи конкретный блокер без новых токенов или grants.

При отклонённом push/ref прочти свежий main в чистом checkout и заново проверь status. Уже queued/complete не дублируй. Повторно готовь запрос только если день не сменился и статус всё ещё pending; при смене дня начни подготовку за текущую дату. Не сливай MP3/смещения и не меняй дату старого запроса. Ожидающий запрос обрабатывает существующий workflow Ryan audio and Pages; его единая очередь, отдельные проверки Ryan/Andrew и часовые повторы уже настроены.

Проверь результат Actions, итоговый аудиокоммит и Pages deployment. После получения нового main проверь соответствие request и data/daily, а на опубликованном сайте — новую карточку, её pack и cache hashes. Не считай успешный push, queued или только unit tests завершённой публикацией. Если задача уже complete в репозитории, не создавай новую карточку; прежде чем назвать её опубликованной, также проверь deployment. Сообщи кратко дату, глагол, commit/run и подтверждённое состояние: опубликовано, ожидает Actions или ошибка. Если job ещё работает, честно сообщи queued; последующие повторы принадлежат существующему workflow.
```
