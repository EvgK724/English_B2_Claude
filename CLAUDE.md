# Английский B2 — объединённое приложение

46 тренажёров английского уровня B1–B2 в одной оболочке: каталог по группам, «Сегодня к повторению», поиск, озвучка, прогресс.
Интерфейс на русском, примеры и задания на английском. Две живые версии, обе ставятся плиткой на экран «Домой» iPhone и iPad:

- GitHub Pages: https://evgk724.github.io/English_B2_Claude/site/ — собирается из этого репозитория (ветка `main`, папка `/`),
  работает без интернета, прогресс — на устройстве (переносится файлом);
- артефакт Claude: https://claude.ai/artifact/15er8g7yJZJ5tCpvRXK3ZM — прогресс синхронизируется через облако claude.ai.

## Структура

```
index.html             перенаправляет корень GitHub Pages на site/
.nojekyll              GitHub Pages отдаёт файлы как есть, без Jekyll
site/                  готовый сайт — именно то, что опубликовано
  index.html           оболочка (собирается скриптом, руками не править)
  sw.js                офлайн-кэш (собирается скриптом из tools/sw.js, руками не править)
  manifest.webmanifest название, иконки и режим приложения для экрана «Домой»
  apple-touch-icon.png, icon-*.png, favicon.png   иконки (tools/render_icons.mjs)
  apps/<ключ>.html     46 тренажёров, каждый — самостоятельная страница
  packs/<ключ>.mp3     все записи тренажёра одним файлом
tools/
  shell.html           шаблон оболочки (стили, каталог, плеер, облачный прогресс, перенос прогресса файлом)
  head.html            <head> страницы: viewport, safe-area, иконки, манифест, режим приложения на iPhone/iPad
  sw.js                шаблон офлайн-кэша
  catalog.json         группы и тренажёры: key, title, group, desc, ids, ls, kw, en
  packs.json           для каждого тренажёра: запись → [смещение, длина, ...] внутри packs/<ключ>.mp3
  mk_shell.py          собирает site/index.html и site/sw.js из shell.html + head.html + sw.js + catalog.json + packs.json
  deck_sync.py         дописывает в phrasal/bbapp карточки и записи из отдельных приложений колод
  render_icons.mjs     рисует иконки (Playwright + шрифт DM Serif Display)
  reference/           исходные скрипты сборки и звука (пути в них — от старой рабочей папки)
sources/<ключ>/        генераторы тренажёров (content.py, build.py, mk_template.py…), для справки
```

## Запуск

Оболочка грузит тренажёры и звук через `fetch`, поэтому двойной клик по `index.html` не работает — нужен локальный сервер:

```
python3 -m http.server 8000
```

Открыть http://localhost:8000/site/ (офлайн-кэш работает и на `localhost`; при отладке его удобно отключить в DevTools → Application).

## Как вносить изменения

- **Тренажёр**: править `site/apps/<ключ>.html`. Данные — в скрипте: `const TOPICS = [...]` (правила и примеры) и `const CARDS = [...]`. В грамматических тренажёрах карточка — `id`, `t` (номер темы), `q` (вопрос с `___`), `opts`, `a` (правильный ответ), `why`; в словарных колодах (phrasal, bbapp, idm и др.) — `id`, `term`, перевод, примеры. Новые карточки делать по образцу соседних. Интервалы повторения — `const INTERVALS = [1, 3, 7, 16]` (дни), ключ прогресса — `LS_STATE = "<ключ>:state"`.
- **Каталог** (название, группа, описание, ключевые слова для поиска): `tools/catalog.json`, затем `python3 tools/mk_shell.py`.
- **Оболочка**: `tools/shell.html` (и `tools/head.html`, `tools/sw.js`), затем `python3 tools/mk_shell.py`. `site/index.html` и `site/sw.js` вручную не править — перезапишутся.
- **После любой правки в `site/apps` или `site/packs`** — тоже `python3 tools/mk_shell.py`: оболочка обращается к файлам с `?v=<хэш содержимого>`,
  и офлайн-кэш на телефоне берёт новую версию только по новому хэшу. Без пересборки устройство продолжит показывать старый файл.
- **Колоды «Фразовые глаголы» и «Фразы из Breaking Bad»** пополняют ежедневные задачи — в отдельных артефактах колод
  (phrasal: https://claude.ai/code/artifact/17f35b77-ec05-4e16-a5e6-516e7ef5f8d8, bbapp: https://claude.ai/code/artifact/63c4fa4f-95e7-4be6-812a-689d838c98c5)
  и в базе артефакта «Английский B2». Чтобы перенести новые карточки сюда: прочитать артефакт колоды (index.html и записи из `audio/` или `audio/us/`)
  в одну папку, затем `python3 tools/deck_sync.py phrasal <папка>` (или `bbapp`) и `python3 tools/mk_shell.py`.
- **Звук**: записи тренажёра склеены в `site/packs/<ключ>.mp3`, смещения — в `tools/packs.json`. Если у фразы нет записи, тренажёр озвучивает её синтезом речи браузера (`TTS_LANG = "en-GB"`). Исходных записей в проекте нет; как их обрезали и склеивали — `tools/reference/audio.py` (нужен ffmpeg).
- `id` карточек не менять: по ним хранится прогресс пользователя.

## Правила оформления

- Тёмная тема, светлый текст без чистого белого (`#e8e8e8`), акцент `#d97757`, синий `#7cc0dd`.
- Крупный шрифт, кнопки не меньше 44×44 px, управление большим пальцем внизу экрана.
- Без горизонтального скролла; проверять ширины 320, 375, 390, 430 (iPhone), 820×1180 и 1180×820 (iPad).
- В русском тексте — неразрывные пробелы после предлогов и между числом и единицей, тире с неразрывным пробелом перед ним.
- Язык объяснений — русский; примеры, задания и ключи — английский.

## Прогресс и облако

Прогресс хранится в `localStorage` (у каждого тренажёра свой ключ). В опубликованном артефакте он ещё синхронизируется
между устройствами через `window.claude` (возможности `db` и `user`); вне claude.ai этого объекта нет, и всё работает на `localStorage`.
Тогда внизу главного экрана показан блок «Прогресс»: «Сохранить прогресс» отдаёт файл `english-progress-<дата>.json`
(на iPhone/iPad — через меню «Поделиться»: AirDrop, «Файлы»), «Загрузить прогресс» сливает файл с текущим прогрессом
по времени ответа (`ts`), как при слиянии с облаком. Офлайн-кэш (`sw.js`) регистрируется тоже только вне claude.ai.

## Публикация

**GitHub Pages.** Сайт раздаётся из ветки `main`, папка `/` (Settings → Pages → Deploy from a branch); корневой `index.html`
перенаправляет на `site/`. Достаточно собрать (`python3 tools/mk_shell.py`), закоммитить и отправить в `main` —
через минуту-две новая версия на сайте, а у установленной плитки — при следующем запуске с интернетом.

**Артефакт.** Чтобы обновить именно его (ссылка и плитки на экране «Домой» сохранятся),
файлы из `site/` публикуют в тот же артефакт — из сессии Claude, где доступен инструмент артефактов.
У `site/index.html` при этом убирают `<head>` из `tools/head.html` (всё до `<body>` включительно) и хвост `</body></html>`:
платформа добавляет свой каркас. `sw.js`, манифест и иконки в артефакт не нужны.
В артефакте пять самых больших пакетов (abbr, htp, idm, irreg, pairs) лежат в хранилище артефакта, поэтому там
список `ASSETS` в `index.html` не пустой; в этой локальной сборке все пакеты — обычные файлы, и `ASSETS = {}`.
